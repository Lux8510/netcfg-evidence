# 解释层模型对比（2026-11-10）

同一批 15 条已标注 Finding，用同一套 system prompt、同一 `temperature=0`、同一引用校验，比较三个模型的解释质量、延迟与成本。

## 结果

| 模型 | 结构接受 | 引用完全正确 | JSON 失败 | 服务错误 | 过度声明 | p50 | p95 | tokens(入/出) | 估算成本 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `mock`（模板） | 15/15 | 15/15 | 0 | 0 | 0 | 0 ms | 0 ms | 0/0 | ¥0 |
| `deepseek-chat` | 15/15 | 15/15 | 0 | 0 | 0 | 1323 ms | 1493 ms | 3687/1632 | ¥0.0204 |
| `deepseek-reasoner` | 15/15 | 15/15 | 0 | 0 | 0 | 2007 ms | 2729 ms | 4062/3179 | ¥0.0671 |

- 案例构成：8 条有明确证据的违规、4 条证据不足（`undetermined`）、3 条跨设备链路 Finding
- 成本按公开列表价估算（chat 入 ¥2/出 ¥8，reasoner 入 ¥4/出 ¥16，每百万 token），仅作量级参考
- 原始响应与逐条结果在 `evals/model-runs/<时间戳>/`，已 gitignore

## 结论

1. **在结构指标上三者打平。** 引用校验只关心规则 ID、行号集合与是否过度声明，这 15 条里没有区分度。
2. **推理档没有带来结构上的收益，但成本约 3.3 倍、p95 延迟约 1.8 倍。** 对“解释已有判定”这种任务，`deepseek-chat` 更合适。
3. **`mock` 打平不代表等价。** 它是模板文本，引用必然正确；它证明流程可跑通，不证明解释有信息量。
4. 结构指标已饱和，说明**真正的差异在语义质量**，而语义质量需要人工盲评，不适合用同一批规则自动打分。

## 对比过程中发现的两个校验器缺陷

1. **跨设备规则 ID 被判为 unknown_rule。** 校验器的已知规则集合只包含 R001–R004，导致 R005–R007 的所有解释被拒绝。已改为包含链路规则。
2. **否定句被当成过度声明。** 文本“本解释不表示已修改或下发任何配置”命中了 `已修改` 正则，被判 `overclaim`。已先剥离否定从句再匹配，并新增回归样例。

这两个问题都是“只有接入真实模型才会暴露”的类型：Mock 从不写否定句，也从不解释链路规则。

## 复现

```bash
make compare
# 或
.venv/bin/python scripts/compare_models.py --models mock,deepseek-chat,deepseek-reasoner
```

## 边界

- 15 条、单次运行，没有统计显著性；要方差用 `--repeat 3`
- 两个模型同属一家厂商，结论不能推广到“所有模型”
- 只评结构，没有评语义；人工盲评不在本次范围
- 价格是估算，厂商调整后需更新 `scripts/compare_models.py` 中的 `PRICES`

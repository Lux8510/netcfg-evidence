### [A02] SSH 登录密码在所有对象表示与持久化路径上都不会泄露

### [A04] 连接、认证和命令异常均显式关闭资源

### [A05] timeout 为整次采集提供有限完成时间

- 结论：反驳
- 位置：collectors/ssh.py:62–70、88–91；安装的 Paramiko Channel.recv_exit_status
- 问题与验证：最小代码路径：连接、banner、认证有超时；exec_command 配置通道等待时间，但 stdout.read() 要读至 EOF。持续有零星输出时，单次读取可不断成功而总时长无界。退出状态等待在本机依赖源码中调用 status_event.wait()，没有 deadline。先读完 stdout 再读 stderr，也不能保证双流持续排空。静态核验，未制造阻塞连接。
- 建议：使用单调时钟截止时间，同时读取两路输出，设置字节上限；超时关闭通道并返回可识别的错误。

### [B01] 前后版本归属不能被改写

- 结论：反驳
- 位置：domain/netcfg/collection.py:139–141、158–170、194–207；engine/models.py:ChangeRun；api/main.py:93–99
- 问题与验证：API 创建和完成时均不接收版本 ID，服务自行采集。最小数据库复现：完成设备 A 的窗口，给设备 B 导入一版，用临时库写会话把 A 窗口的 before_version_id 更新为 B 的有效 ID；实测更新 1 行，详情 API 返回 B 版本。after 同样只有单列外键；存储的差异不会因换绑重算。另外，在同一设备两次采集之间修改 SSH 目标，服务也不会校验物理目标连续性。
- 建议：绑定设备与版本的组合外键，保护已写入的 before 和已完成结果；在窗口保存目标身份，完成前核对。

### [B02] 同一窗口至多有一次完成结果

- 结论：反驳
- 位置：domain/netcfg/collection.py:147–177；engine/models.py:ChangeRun
- 问题与验证：最小复现：临时 SQLite 中让两个会话都持有同一条 open 记录。第一个用采集替身返回 v1 并提交；第二个保留旧对象，用 v2 完成并提交。实测两次均成功且 after_version_id 不同，最后提交者覆盖结果。按新请求串行再读会返回 409；这不能保护重叠读取。
- 建议：采集前按 id 和 status=open 原子占用窗口，只有胜者能生成 after；对已完成重试返回既有结果或明确冲突。

### [B03] 采集失败既不新增版本，也留下 failed 窗口和事件

### [01] 撤销显式 cost 后，R001 仍计为符合

- 结论：接受
- 位置：`domain/netcfg/parser.py:_parse_interface_line`、`domain/netcfg/rules.py:check_p2p_requires_cost`
- 问题：导入下列文本再运行规则检查。第 4 行撤销第 3 行，解析器却保留 cost=10。第 4 行进入 unparsed，但不匹配以 ip ospf 开头的未知行检查。实测 HTTP 201，四条规则全部 satisfied，undetermined 为 0。

  ```text

   ip ospf network point-to-point
   ip ospf cost 10
  ```

- 建议：在当前接口按顺序处理 no ip ospf cost，清除 cost 并保留撤销行作为 R001 证据。对尚未支持的同类否定命令，按接口和字段返回 undetermined。

## 总体判断

这是一套可以演示「导入 → 设基线 → 比对 → 回查原文」的 W1 原型。SQLite 的唯一约束在实际竞争中守住了两项数据约束。当前最影响可信度的是：文本里已有反证，系统仍可能判符合；有时找到了正确的变更字段，却引用另一条未改的配置行。

**最该补的三件事**

1. 用 [01] 与 [08] 固定规则边界，区分已符合、缺少信息和不适用。
2. 让 [06] 的第二地址改动指向正确原文，把两端值和证据行纳入独立评测。
3. 把 [03]、[04] 的可控交错固定为回归用例，让重复导入返回已有版本，让竞争改基线返回明确冲突。

**面试时最容易被问倒的三个点**

1. 为什么 no ip ospf cost 会让配置实际撤销 cost，规则仍报符合？检查依据是哪一行？
2. 为什么数据库只有一条记录，两个调用方仍会看到不同结果？失败方该如何重试？
3. 20/20 究竟验证了什么？如果新旧值颠倒、行号指向另一条地址，哪个测试会失败？
